InspectFlow

Pass or reject decisions for parts on a conveyor, made two ways: with hand-tuned OpenCV rules, and with a small CNN I trained in PyTorch and run on the CPU through ONNX.

Rules, poor light

CNN, poor light

CNN, one CPU core
23 ms a frame

The belt is simulated, so every decision at the gate can be checked against the part's true label. That separates the two mistakes a real line cares about: a bad part shipped and a good part scrapped.

The rules check color against a fixed reference, so a moving spotlight pushes good parts out of tolerance. The CNN never saw a spotlight in training and still gets every part right. When it first scored perfectly I suspected a leak in my own test scenes, found one way it could happen, and rebuilt the generator to rule it out. Flat-field correction, the usual fix for the rules, found more parts but made the size measurements worse.

Python, OpenCV, PyTorch, ONNX, FastAPI and plain JavaScript, packaged with Docker and tested in GitHub Actions.

The scenes are synthetic. The CNN has not been tested on camera footage.
